# Provenance

Tonic Clap is a clean-room reimplementation released under the BSD 3-Clause license.

## What it is based on

| Area | Source |
|------|--------|
| Compute backend | ccv / nnc by Liu Liu (BSD-3), vendored unchanged except as listed in `third_party/ccv/README.md` |
| Safe nnc wrapper (`crates/nnc`) | design ideas from s4nnc (BSD-3, Liu Liu) |
| FLUX.2 transformer, VAE, pipeline, scheduler | public architecture description and Apache-2.0 reference code (Black Forest Labs, Hugging Face diffusers) |
| Qwen3 text encoder | Apache-2.0 reference code (Hugging Face transformers) |
| Seeded noise | PyTorch's (BSD) CPU normal-sampling algorithm, verified against `torch.randn` |
| Tensor compression | LLNL fpzip (BSD-3), vendored |

## Interface compatibility

The command line flags, the gRPC service definition and messages, the
`GenerationConfiguration` FlatBuffers layout and the image tensor wire format are
functional interfaces of the Draw Things software. They were documented in
[INTERFACE.md](INTERFACE.md) from their observable/declared form (flag names, protocol
field names and numbers, schema field order, byte layout) so that existing clients keep
working; no implementation code from Draw Things was used.

## Draw Things checkpoint files (`.ckpt`)

Tonic Clap reads the weight files Draw Things stores in its models folder. Draw Things' own
source code (GPL-3) was **not** used. What the reader and the name mappings rely on:

| What | Source |
|------|--------|
| SQLite layout: `tensors(name, type, format, datatype, dim, data)`, `tensor_splits`, codec identifier in the high 32 bits of `type` | `third_party/ccv/lib/nnc/ccv_nnc_tensor_io.c` (BSD-3) |
| Codecs: q8p (block size, per block 256 palette entries + u8 indices), ezm7 (deflated exponents + sign/7-bit mantissa bytes), zip, fpzip; external store (`0x1000_0000` bit, `offset`/`length` payloads, `-tensordata` sidecar, trailer store at big-endian bytes 60..64) | s4nnc `nnc/Store.swift` (BSD-3, https://github.com/liuliu/s4nnc) |
| Tensor names, shapes and their correspondence to BFL / diffusers / transformers names | observed in the published files and established by comparing values with the official weights (below) |
| FLUX.2 [klein] 9B-KV behaviour (reference tokens first, timestep-0 modulation, reference tokens attend only to themselves) | diffusers `Flux2KleinKVPipeline` / `transformer_flux2.py` (Apache-2.0); model card of black-forest-labs/FLUX.2-klein-9b-kv |
| VAE latent batch-norm statistics (absent from Draw Things' VAE file) | `crates/tc-core/src/models/flux2_vae_bn.rs`, generated by `scripts/gen_vae_bn.py` from the Apache-2.0 black-forest-labs/FLUX.2-klein-4B VAE |
| Public file names and download location | `https://models.drawthings.ai/models_sha256.json`, `https://static.libnnc.org/<file>` |

"kv" in `flux_2_klein_9b_kv_q8p.ckpt` is BFL's **FLUX.2 [klein] 9B-KV** release: same
architecture and tensor names as 9B, different weights, and the KV reference conditioning above.

### Verification (October 2026)

Files from `static.libnnc.org`, SHA-256 matching the published manifest. "rel" is
`||a - b|| / ||b||` per tensor.

* **Transformer** `flux_2_klein_9b_kv_q8p.ckpt` (382 tensors: 297 q8p, 80 ezm7, 5 raw f16) against
  BFL's 9B-KV weights in the `QuantStack/FLUX.2-Klein-9B-KV-GGUF` Q8_0 file (`scripts/ckpt/verify_flux2.py`,
  HTTP range reads): every tensor maps; q8p tensors rel ≤ 0.90% (the sum of the q8p and Q8_0
  quantization noise; a wrong slice or permutation gives ≥ 100%), embedders, final linear and all
  norm scales identical. Found this way: the final-layer modulation is stored as (scale, shift),
  BFL's order is (shift, scale); single-block `linear1` is split into q, k, v, w1, w3 and `linear2`
  into o (attention columns) and w2 (MLP columns). Functional check
  (`examples/flux2_reduced_parity.rs`, embedders + first double + first single block + final layer,
  CPU f32): `.ckpt` vs reference outputs rel 0.092% (plain) and 0.087% (KV variant).
* **Qwen3-8B** `qwen_3_8b_q8p.ckpt` (398 tensors) against `Qwen/Qwen3-8B` (`scripts/ckpt/verify_qwen.py`):
  every tensor maps; q/k projections and q/k norms are stored with rows in the interleaved
  rotary order (rel 0.61% after that permutation, 140% without), all other tensors rel ≤ 0.65%,
  embeddings and norms identical.
* **VAE** `flux_2_vae_f16.ckpt` (248 raw f16 tensors, positional names `__encoder__[t-K-0/1]`):
  the module order was found by matching every tensor by value against the FLUX.2-klein-4B
  diffusers VAE; through the Rust loader (`draw-things-cli models compare`) all 248 tensors rel ≤
  0.22% (bf16 rounding of the reference). Encoding / decoding a test image (`examples/vae_parity.rs`):
  latents rel 0.72%, decoded image rel 0.17%.
* **LoRAs** converted by Draw Things (the two files used for testing, f16, rank 32): tensors are
  `<model tensor>__down__` `[rank, in]` and `__up__` `[out, rank]` for each adapted model tensor,
  with no alpha stored; all 280 updates of each map onto 136 transformer parameters with matching
  shapes. Unit tests check that this layout reproduces a PEFT LoRA exactly. Whether Draw Things
  folds the original alpha / rank into the stored weights (assumed: scale 1) has not been checked
  against the original Civitai files; `draw-things-cli models compare <lora.ckpt> <original.safetensors>`
  reports the best-fit scale.

## What was deliberately not reused

Draw Things' model definitions, model zoo, samplers and generation pipeline are not reproduced,
and none of its source code was read. Its checkpoint files are read as data, as described above.
